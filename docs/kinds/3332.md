# Kind 3332 — Story view receipt (Chatme custom, prototype)

**Status:** Chatme prototype, not a NIP. It only has meaning together with Chatme's [kind 3331 story format](3331.md).

**Purpose:** tell a story's author that one of their contacts opened the story, so the author's **N views** pill and viewers panel can update.

**Transport:** a kind `3332` rumor inside the standard NIP-17 envelope: seal kind `13`, gift wrap kind `1059`, NIP-44 encryption. See the [kind index](README.md) for the shared envelope and validation rules.

## Rumor shape

| Field | Value |
| --- | --- |
| `kind` | `3332` |
| `pubkey` | Viewer's public key, authenticated by the seal. |
| `created_at` | Unix seconds. The receiver uses this as the viewed-at timestamp. |
| `tags` | `p` = story author, `e` = story id. The story id must be 64 lowercase hex. |
| `content` | `viewed`. |
| `id` | NIP-01 sha256 of `[0, pubkey, created_at, kind, tags, content]`. No `sig` on the rumor. |

Illustrative rumor:

```json
{
  "pubkey": "<viewer 64-hex pubkey>",
  "created_at": 1760000500,
  "kind": 3332,
  "tags": [
    ["p", "<author 64-hex pubkey>"],
    ["e", "<64-hex story id>"]
  ],
  "content": "viewed",
  "id": "<64-hex sha256 event id>"
}
```

## Send behavior

- A receipt is attempted whenever the viewer opens a story, including a repeat open. The author deduplicates by viewer public key, so repeat receipts do not add extra viewers.
- No receipt is sent for the viewer's own story, when there is no relay manager, when the identity is incomplete, or when the story id is not a canonical 64 lowercase hex string.
- The wrap is broadcast to all connected relays that are up. There is no retry queue for a failed or dropped receipt.
- The receipt is separate from the local view state. The viewer's own ring turns gray from its local record; the receipt only helps the author's view count.

## Receiver behavior

1. Unwrap and verify the NIP-17 layers. The inner kind must be one of the kinds Chatme accepts.
2. Take the first valid `e` tag as the story id. An invalid or missing id is ignored.
3. Ignore a receipt whose sender is the local user.
4. Require the story to exist locally and its author to be the local user.
5. Ignore a receipt from a viewer who is already recorded for that story.
6. Otherwise store the viewer with the rumor's `created_at` converted to milliseconds, then refresh the story UI.

The `p` tag names the author, but the receiver trusts the authenticated seal sender as the viewer and checks the story row locally. A forged receipt cannot add a viewer to somebody else's story.

## Compatibility and limits

- Other clients have no standard behavior for kind `3332`; they should ignore it.
- Delivery is best-effort. If relays drop the receipt, the author's viewers list simply lags; there is no polling or recovery handshake.
- Only one bit of information is carried per viewer: that the story was opened. Chatme does not report how long it was watched or whether playback finished.
- The viewed-at timestamp comes from the sending device's clock, not from the relay.
